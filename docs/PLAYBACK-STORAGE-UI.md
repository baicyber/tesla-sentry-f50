# 连续播放、行车记录与存储管理

本改动基于上游 `main` 的 `0bc122bd9808a49881b6aac5bd20fcf9aba8b38b`，汇集 F50 上已有的播放、归档、安装和界面改进。保留上游许可证、通用安装入口和版本发布工具；`APP_VERSION` 与现有 `version.json` 保持一致，正式版本号由维护者发布时确定。

## 播放和时间轴

- 哨兵录像、手动保存、最近一小时、行车记录和实时预览共用播放控制，支持单路和多路切换、播放暂停、拖动及连续切段。
- 当前片段转码完成后继续准备下一段，按播放请求优先级调度；保留温度保护和缓存空间限制。
- 多路播放在缺少可播数据时协调暂停和恢复，快速拖动后丢弃旧请求及过期媒体事件，优先补齐落后的视角。
- 按媒体时长组织播放区间，保留时间戳重叠片段的内容；保留原始文件，不自动去重。
- 仅对超过 0.5 秒的缺失显示与时间轴区间对应的白色标记，最小宽度为 1 像素。悬停可查看缺失说明；自动跳过时不再用提示改变页面布局，主动点击、拖动时保留反馈。
- 修复加载期间播放/暂停意图丢失、按钮状态不响应，以及部分视角等待过久的问题。

## 行车记录和录像管理

- 新增独立的 `DriveClips` 行车记录，保留各摄像头原始文件；根据挡位和停车时长识别行程，按连续时间组织展示。
- 容量达到上限时按顺序清理较旧行程，继续接收新录像；受保护的录像不参与自动清理。
- 归档播放器可锁定、解锁或删除录像；行车记录按当前展示的整段行程操作。
- 最近一小时和实时预览保留循环录像的只读操作边界。
- 删除与同步、清理及文件管理共用保护检查；记录删除状态，避免已删除录像被重新复制。锁定信息无法可靠读取时拒绝修改，保留浏览能力。

## 存储和安装

- 设置界面展示车机 U 盘、盒子归档、行车记录额度、缓存预算和空闲预留的关系，并提供小型帮助按钮。
- 归档额度通过 `storage.json` 保存，清理和同步读取同一份配置。
- 调整车机 U 盘容量须明确确认清空 U 盘内容；盒子归档保留。操作重建 exFAT 镜像并恢复 USB 导出，不执行视频迁移。
- 新增 ARM64 OpenWrt 专用的 `install-f50.sh`、安装器、启动服务和离线包构建工具。通用部署继续使用原有 `install.sh`。
- 离线构建工具接受已准备并校验的 ARM64 运行环境，保留依赖清单、哈希和许可证。本 PR 不包含运行环境二进制，也不发布离线安装包。

安装步骤、容量调整影响及失败恢复边界见 [全新 F50 安装](INSTALL-F50.md)。

## 界面

录像首页、播放器和设置采用统一的简洁管理界面，并适配窄屏。顶部状态栏显示 CPU 温度、CPU 使用率和内存状态；统一“行车记录”名称，移除重复的存储跳转入口，调整播放按钮和容量帮助控件。

## 部署与兼容边界

- `sentry-viewer.py` 和 `tesla-live-sync.py` 新增对同目录存储模块的依赖。必须同时部署 `storage_allocation.py`、`storage_resize.py` 及配套脚本；不能只复制主程序。
- 本次只为上游通用安装器补充配套文件复制；F50 专用安装器作为独立入口，默认仅检查，显式指定 `--apply` 才执行安装。
- 旧版 OTA 采用主程序临时加载检查，并只更新已存在的配套脚本，无法直接为本改动补齐新模块。维护者发布前需要安排多文件升级流程；本 PR 使用完整源码部署，不能视为已经完成旧设备网页 OTA 兼容。
- 现有验证集中于 F50、较新 Python 和 Chrome。上游声明的旧 Python、其他 Linux 平台、六摄像头和 iPhone/Safari 原生 HLS 尚未对本改动重新验收。
- 容量调整涉及 USB 断开和重建，断电后的恢复仍需核对现场状态。空白 F50 的完整物理安装、冷启动及车机识别未完成端到端验收。
